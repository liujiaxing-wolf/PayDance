# 发布、回滚与恢复

## 1. 发布模型

| 类型 | 用途 | 允许的签名方式 |
|---|---|---|
| 本机验收 | 开发与当前电脑验收 | 临时签名 |
| 内部测试 | 受控测试成员 | Apple Development/Developer ID，按团队规范 |
| 公开发布 | 面向普通用户 | Developer ID 签名、公证、stapling 和可信下载渠道 |

不得把临时签名 Debug 应用包装成正式公开版本。

## 2. 版本与标签

- 公开版本采用语义化版本 `MAJOR.MINOR.PATCH`；
- 每个发布版本对应唯一 Git 提交和带注释标签；
- 构建号单调递增；
- CHANGELOG 记录新增、变更、修复、安全与不兼容事项；
- 产物保存 SHA-256、签名信息和构建时间。

## 3. 发布步骤

1. 冻结范围并执行发布检查清单；
2. 从批准分支构建 Release；
3. 完成签名、公证、stapling 和签名验证；
4. 在干净账户测试安装、首次启动、升级和卸载；
5. 小范围发布并观察启动、崩溃、权限和文件写入；
6. 达到停止条件立即暂停发布或回滚；
7. 完成后归档代码提交、产物、哈希、测试报告和已知问题。

## 4. 回滚触发条件

- 启动即崩溃或高频闪退；
- 收益计算错误造成显著误导；
- 日历事项丢失或破坏用户数据；
- 截图/录屏越权、隐私泄露或无法停止；
- 安装升级造成应用不可恢复；
- 出现高危依赖或签名安全事件。

## 5. 应用回滚

1. 停止继续分发问题版本；
2. 保留问题版本日志、提交号和用户影响范围；
3. 使用前一个已验收标签重新构建，或恢复已归档的已签名产物；
4. 不删除 `~/Library/Application Support/Atoll`，除非确认数据本身损坏；
5. 启动旧版本，验证收益、日历、快捷键和输出目录；
6. 发布事故说明并建立修复分支。

当前可回退代码节点：

| 阶段 | 分支 | 提交 |
|---|---|---|
| Phase 1 最终版 | `第一阶段开发最终版` | `e767ebc` |
| Phase 2 最终版 | `第二阶段开发最终版` | `0efcace` |

回退到 Phase 1 会失去 Phase 2 功能，执行前必须确认数据兼容性。

## 6. 数据备份与恢复

退出 Atoll 后，备份以下目录：

```text
~/Library/Application Support/Atoll/LiveEarnings/
```

另行备份用户需要保留的：

```text
~/Pictures/Atoll Screenshots/
~/Movies/Atoll Recordings/
```

恢复时先退出 Atoll，将经过确认的备份覆盖回同一路径，再启动并检查配置与日历事项。不要从不受信任来源恢复 JSON 或媒体文件。

## 7. 数据损坏处理

- 先复制问题文件用于诊断，不要立即删除；
- 确认 JSON 可解析、文件权限正常、磁盘空间充足；
- 优先只隔离损坏文件，不清空整个应用支持目录；
- 恢复后记录损坏文件、应用版本和复现路径；
- 涉及用户日历或 API Key 时，日志必须脱敏。

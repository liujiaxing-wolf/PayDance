# 第三方依赖与许可证

## 1. 项目许可证现状

| 资产 | 已发现声明 | 处理要求 |
|---|---|---|
| Atoll 源码 | GPL-3.0 | 保留许可证和版权声明，分发衍生作品前确认 GPL 义务 |
| PayDance/薪跳来源源码 | AGPL-3.0-only | 行为与需求参考需保留来源记录；如复用代码，必须单独确认 AGPL 兼容与网络交互义务 |
| 融合实现 | 以 Atoll 仓库实际代码和最终法律审查为准 | 公开分发前形成书面许可证结论 |

本项目文档不能替代法律意见。当前结论仅用于识别风险，不授权忽略任一上游许可证。

## 3. 发行前依赖清单要求

每次正式发布应从 `Package.resolved`、Xcode resolved packages、源码子模块和二进制框架自动生成实际清单，并记录：

| 字段 | 要求 |
|---|---|
| 名称与来源 | 官方仓库或供应商 URL |
| 精确版本 | tag、commit 或二进制版本 |
| 许可证 | SPDX 标识与原始 LICENSE 文件 |
| 使用方式 | 源码、静态/动态链接、服务 API、仅参考 |
| 修改情况 | 是否修改上游代码 |
| 发行义务 | NOTICE、源码提供、署名、许可证副本等 |
| 风险状态 | 已审核、需复核、禁止发行 |

## 4. 合规动作

1. 保留 Atoll 与 PayDance 的 LICENSE、版权和来源信息；
2. 区分“参考产品行为”“重写实现”和“复制源码”；
3. 对直接复制或修改的代码保留文件级来源记录；
4. 将所有发行所需许可证文本和 NOTICE 放入应用或分发包；
5. 核对图标、截图、字体、音效和品牌素材的使用权；
6. 对 AI 服务商、天气、更新源等外部服务保留服务条款和隐私说明；
7. 升级依赖时重新执行安全与许可证审查。

## 5. 禁止事项

- 不根据包名猜测许可证；
- 不把 GitHub 可访问等同于可自由商用；
- 不删除上游版权头、LICENSE 或 NOTICE；
- 不把 AGPL/GPL 项目改名后宣称为闭源自有代码；
- 不在未审查时向公众发布包含未知二进制框架的产物。

## 6. 当前缺口

当前仓库已有许可证、贡献和第三方 Notice 检查基础，但尚缺一份由实际 Release 产物反向生成、逐项确认版本和许可证的最终 SBOM/NOTICE。因此公开发布检查清单中的第三方合规项保持未完成。

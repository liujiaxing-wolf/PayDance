# 数据存储与生命周期

## 1. 数据分类

| 数据 | 敏感级别 | 事实来源 | 存储 | 网络传输 |
|---|---|---|---|---|
| 薪资与工作时间 | 高 | 用户输入 | Defaults 中的 LiveEarnings 配置 | 融合功能不上传 |
| 日期例外 | 中 | 用户操作 | `overrides-v1.json` | 不上传 |
| 收益历史 | 高 | 本地计算 | `history-v1.json`、`pending-day-v1.json` | 不上传 |
| Atoll 管理事项 ID | 中 | EventKit 创建结果 | `calendar-items-v1.json` | 不上传；实际事项由 EventKit 管理 |
| 日历/提醒内容 | 高 | macOS EventKit | 系统日历/提醒事项数据库 | 由用户系统账户同步策略决定，不由本项目控制 |
| 截图 | 高 | 用户主动捕获 | PNG 文件 | 不自动上传 |
| 录屏及音频 | 极高 | 用户主动捕获 | MP4 文件 | 不自动上传 |
| 捕获偏好和目录书签 | 中 | 用户设置 | Defaults `capturePreferences.v1` | 不上传 |
| AI API Key | 极高 | 用户输入 | 当前为 Defaults | 作为鉴权头发送给对应供应商；不应进入日志 |
| AI 消息/附件 | 极高 | 用户主动发送 | 取决于 Atoll Screen Assistant 实现 | 发送给所选供应商 |

## 2. 融合模块本地路径

根目录：

```text
~/Library/Application Support/Atoll/LiveEarnings/
```

| 文件 | 内容 | 格式与保护 |
|---|---|---|
| `overrides-v1.json` | 日期类型和当天日程覆盖 | schemaVersion、revision、原子写入、解码复核 |
| `history-v1.json` | 已完成日期收益快照 | schemaVersion、revision、原子写入、已完成记录不可随意重写 |
| `pending-day-v1.json` | 跨生命周期待固化的当前日信息 | 清除历史时同步移除 |
| `calendar-items-v1.json` | Atoll 创建的日程/提醒 ID 和类型 | schemaVersion、revision、原子写入 |

捕获默认目录：

```text
~/Pictures/Atoll Screenshots/
~/Movies/Atoll Recordings/
```

自定义目录通过 security-scoped bookmark 保存。书签失效时必须要求用户重选，不得静默改存其他位置。

## 3. 生命周期

### 3.1 创建与更新

- 配置修改自动保存并触发重新计算。
- JSON Store 使用临时内存文档、revision 和原子写入。
- 截图先写隐藏临时 PNG，编码和大小校验后移动到最终名称。
- 录屏先写隐藏临时 MP4，完成封装与校验后转为最终文件。

### 3.2 保留

- 配置和历史默认长期保留，直到用户清除或删除应用数据。
- 截图/录屏由用户自行管理，不自动上传，也不自动定期删除。
- 日历和提醒事项保留策略由 macOS 日历/提醒事项服务决定。

### 3.3 删除

- 清除收益历史：删除历史和 pending day，不删除薪资配置。
- 清空全部事项：删除 Atoll 管理范围内的日程与待办，并清理 registry；必须二次确认。
- 单项删除：只删除用户确认的目标项。
- 删除截图/录屏：使用访达或未来文件管理入口；应用不得偷偷删除其他文件。

### 3.4 备份与恢复

手工备份前退出 Atoll，然后复制 `~/Library/Application Support/Atoll/LiveEarnings/`。恢复时确保目标版本支持相同 schemaVersion。截图录屏按普通文件备份。

## 4. 数据损坏处理

1. 不覆盖原损坏文件。
2. 记录不含敏感正文的错误类型和文件名。
3. 将原文件复制为带时间戳的备份（实现恢复工具前由维护者手动执行）。
4. 仅在用户确认后恢复默认空 Store。
5. 不通过“忽略解码错误并保存空文件”静默丢数据。

## 5. 数据迁移规则

- 每个持久化文档包含 `schemaVersion`。
- 新版本必须向后读取旧版本或提供显式迁移器。
- 迁移先备份、再转换、再解码复核，最后原子替换。
- 不支持的未来版本应明确报错，不降级覆盖。

## 6. 安全债

AI 供应商 Key 当前由 Defaults 保存和读取。正式公开发布前建议迁移到 Keychain：写入确认成功后才清除 Defaults 旧值；迁移失败保持旧值但提示用户，不得打印 Key。

# 架构决策记录

> 本文件采用精简 ADR 格式。状态包括“已接受”“已取代”“提议”。未来重大变更应新增记录，不直接改写历史理由。

## ADR-001：Atoll 是唯一运行宿主

- 状态：已接受
- 日期：2026-08-25
- 决策：融合功能使用 Swift/SwiftUI 原生实现；PayDance Vue/Tauri 外壳不进入产物。
- 理由：保留 Atoll 刘海、窗口、权限和发布体系，避免双应用和跨运行时复杂度。
- 影响：PayDance 只作为行为和规则参考；直接复制代码前必须审查 AGPL/GPL 边界。

## ADR-002：一期、二期仅支持 macOS 刘海设备

- 状态：已接受
- 决策：正式范围为 macOS 14.6+、Apple Silicon、带实体刘海的 MacBook。
- 理由：产品核心交互依赖实体刘海，有限资源优先完成真实体验。
- 影响：Windows、Web、Intel、无刘海和多显示器不进入当前验收。

## ADR-003：实时收益采用纯计算引擎与本地配置

- 状态：已接受
- 决策：金额和状态由 `LiveEarningsEngine` 根据配置、日程和当前时间计算。
- 理由：可测试、无需服务器、隐私风险较低，恢复唤醒时可重新计算而不是依赖计数器。
- 影响：UI 不得重复公式；不保存每秒金额。

## ADR-004：手动日期例外优先

- 状态：已接受
- 决策：用户当天例外 > 官方规则包 > 固定星期。
- 理由：个人请假和临时工作比公共规则更具体。
- 影响：界面需显示来源并提供恢复自动判断。

## ADR-005：历史使用完成日快照

- 状态：已接受
- 决策：已完成日期固化当时配置和最终收益，后续全局配置不重算旧记录。
- 理由：保证历史稳定和可解释。
- 影响：纠错需未来显式修订流程，不能后台静默改写。

## ADR-006：捕获只面向内置屏幕

- 状态：已接受
- 决策：二期不提供显示器选择器，仅解析 MacBook 内置显示器。
- 理由：用户明确排除多显示器；控制权限、UI 和测试复杂度。
- 影响：只剩外接屏或内置屏不可用时禁用并说明。

## ADR-007：捕获文件本地保存且不经过剪贴板中转

- 状态：已接受
- 决策：截图直接编码 PNG，录屏直接写 MP4，最终按用户操作复制或打开。
- 理由：避免污染剪贴板、减少丢失和格式不确定性。
- 影响：文件 Store 必须处理目录书签、重名、临时文件和失败恢复。

## ADR-008：关闭态采用固定翼宽和自适应数字

- 状态：已接受
- 决策：保持摄像头居中和左右紧凑，不随金额无限扩宽；数字按整数位数缩放。
- 理由：同时解决数字被实体刘海遮挡与菜单栏应用被覆盖。
- 影响：超长数字可读性有限，但不能破坏系统菜单栏空间。

## ADR-009：工作日历是独立顶部标签

- 状态：已接受
- 决策：取消 Home 下方嵌入小日历，使用顶部独立标签进入完整月历。
- 理由：完整编辑需要稳定空间；避免 Home 裁切和月份高度不一致。
- 影响：标签切换时日历及事项标志必须作为同一视图同步转场。

## ADR-010：日期双击打开统一事项面板

- 状态：已接受
- 决策：移除顶部“查看 N 项”，所有日期双击均打开同一管理面板。
- 理由：查看与创建入口统一，空日期也能直接添加。
- 影响：单击只选中，双击打开；需保证手势不互相吞掉。

## ADR-011：Home 收益进度条固定绿色

- 状态：已接受
- 日期：2026-08-26
- 决策：显式使用 `LinearProgressViewStyle` 和 `#30D158`，不依赖系统普通 `.tint()`。
- 理由：原生样式在当前容器中显示为灰色；用户要求绿色。
- 影响：刘海数字仍可由用户选色，Home 进度条不跟随该颜色。

## ADR-012：本机验收采用临时签名

- 状态：已接受（仅本机）
- 决策：缺少上游 Team ID 对应私钥时，用 `CODE_SIGNING_ALLOWED=NO` 构建并执行 ad-hoc 签名。
- 理由：允许当前电脑真实验收，不冒用或索取上游私钥。
- 影响：产物不能代表正式发行；公开分发必须走 Developer ID 与公证。

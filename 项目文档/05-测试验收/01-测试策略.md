# 测试策略

## 1. 目标与原则

本策略用于证明 Atoll × 薪跳在目标设备上的核心能力可构建、可运行、可恢复，并避免把“编译成功”误认为“产品可验收”。测试遵循风险优先、分层验证、真实设备最终确认和证据可追溯原则。

## 2. 测试范围

| 范围 | 主要验证内容 |
|---|---|
| 实时收益 | 薪资换算、上下班与午休、工作日覆盖、暂停/恢复、进度条和刘海金额自适应 |
| 工作日历 | 月份切换、日期类型、日程/待办新增、查看、修改、完成、删除、清空及持久化 |
| 截图录屏 | 区域/窗口/全屏截图，区域/全屏录制，权限失败提示，输出文件 |
| 快捷键 | 录制、冲突检测、恢复默认、重启持久化与全局触发 |
| Atoll 原能力 | Home、标签页、设置、刘海展开/收起等回归 |
| 安全与隐私 | 权限文案、本地数据、密钥不进入仓库、日志不泄露敏感信息 |

不在当前验收矩阵内：Windows、Web、Intel Mac、无刘海设备、多显示器、复杂排班、云同步和公开视频分发。

## 3. 分层测试

### 3.1 L0：静态检查

- `git diff --check`：空白与补丁格式。
- 检查 `Info.plist` 权限说明和隐私相关配置。
- 检查源码、文档和提交中无 API Key、私钥、令牌或用户数据。
- 检查需求追踪矩阵与变更范围同步。

### 3.2 L1：自动回归

在 `/Users/Apple/Desktop/Atoll` 执行：

```bash
python3 -m unittest discover -s tests -p 'test_*.py'
```

任何失败均阻止交付。新增缺陷应先增加可复现测试，再修复实现。

### 3.3 L2：构建检查

```bash
xcodebuild \
  -project DynamicIsland.xcodeproj \
  -scheme DynamicIsland \
  -configuration Debug \
  -destination 'platform=macOS' \
  build \
  CODE_SIGNING_ALLOWED=NO
```

通过条件：命令返回 0 且输出 `BUILD SUCCEEDED`。发行候选还必须使用有效开发者身份完成签名构建。

### 3.4 L3：本机冒烟与回归

在带实体刘海的 Apple Silicon MacBook 上安装最新产物，按以下顺序测试：

1. 首次启动、权限引导、实时收益设置与刘海静默数字；
2. Home 展开、Atoll 原标签页、收益卡片与设置入口；
3. 工作日历完整月份、不同月份高度、双击任意日期、事项 CRUD 与清空；
4. 截图和录屏五类入口、快捷键配置及输出目录；
5. 修改薪资/工作时间后金额与进度立即刷新；
6. 退出重启后配置、历史、日历事项和快捷键仍存在；
7. 拒绝权限、磁盘不可写、快捷键冲突等失败路径有明确提示。

### 3.5 L4：用户验收

验收人依据 [需求追踪矩阵](../02-产品需求/02-需求追踪矩阵.md) 和阶段清单逐项确认。涉及视觉与交互的结论以真实刘海设备为准，截图只能作为辅助证据。

## 4. 缺陷等级

| 等级 | 定义 | 发布规则 |
|---|---|---|
| P0 | 数据破坏、安全事故、应用无法启动 | 必须修复 |
| P1 | 核心流程不可用、频繁闪退、刘海严重遮挡 | 必须修复 |
| P2 | 有绕行方案的功能或视觉问题 | 明确记录后决定 |
| P3 | 轻微文案、间距或建议项 | 可进入后续版本 |

## 5. 退出标准

- L0、L1、L2 全部通过；
- 核心用户旅程 L3 全部通过；
- 无未解决 P0/P1；
- 已知 P2/P3 已进入风险登记册或路线图；
- 验收人明确确认；
- 代码提交、构建产物和文档版本可互相追踪。

## 6. 证据保留

测试证据至少记录日期、分支、提交、设备范围、命令结果、失败项和验收结论。不得在证据中包含真实 API Key、录屏隐私内容或个人日程正文。

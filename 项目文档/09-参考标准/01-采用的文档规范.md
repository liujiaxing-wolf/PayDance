# 采用的公开文档规范

## 1. 调研目的

本项目没有机械套用大型企业模板，而是从公开、权威规范中选取适合单机 macOS 产品收尾的最小完整集合：贡献与社区健康、文档类型、架构表达、安全开发、威胁建模、版本和变更记录。

## 3. 文档集合裁剪

### 已保留或补齐

- 项目入口、章程、范围、里程碑、风险、结项交接；
- PRD 基线、需求追踪、用户手册、限制与路线图；
- 系统架构、数据生命周期、ADR；
- 开发、构建、配置、权限和提交规范；
- 测试策略、最终报告、发布清单；
- 部署、回滚、恢复、故障排查；
- 安全隐私、威胁模型、第三方许可证；
- 历史索引、术语与文档治理。

### 暂不单独建立

- 独立 SLA/SLO：当前没有在线服务和对外服务承诺；
- API 参考：当前没有公开服务端 API；
- 数据库运维手册：当前采用本地文件和 UserDefaults；
- 多团队 RACI：当前协作规模不足以支撑复杂角色矩阵；
- 灾备机房方案：不适用于本地单机应用。

如果后续加入云同步、账号、自动更新后台或团队协作，应新增 API 契约、数据处理协议、SLA/SLO、生产值班和服务端灾备文档。

## 4. 格式约定

- Markdown 为主，标题从一个 H1 开始并按层级递进；
- 表格用于明确映射，流程和边界用 Mermaid；
- 命令必须注明工作目录、前置条件和成功标志；
- 事实、验收结论、计划和风险分开书写；
- 外部规范链接到官方或原始来源，不复制大段受版权保护文本；
- 文档中的版本、提交、路径和日期必须可核验。

## 5. 审查结论

以上规范支持当前文档集达到“可理解、可构建、可测试、可部署、可回滚、可交接”的项目收尾目标。它不意味着产品已经完成公众分发所需的签名、公证、许可证法律审查和多设备兼容验证。
